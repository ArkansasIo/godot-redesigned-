02 / ENGINE LAYERS

Navigate the full source architecture

Use the repository paths as the primary map into the engine. The labels below describe the major responsibilities rather than replacing upstream source organization.

core/Foundational data types, object system, containers, math, Variant, resources, utilities, threading, and engine primitives.
scene/Node and scene runtime, GUI controls, animation, 2D, 3D, resources, main loop integration, and gameplay-facing APIs.
servers/Rendering, physics, audio, navigation, text, XR, and other service interfaces used by the runtime.
editor/Godot's native authoring environment, docks, inspectors, scene tools, import UI, debugger, scripting tools, and plugins.
platform/Operating-system and device integrations including display, input, filesystem, process control, networking, and platform services.
modules/Optional and integrated engine modules, including the project-specific redesign module.
drivers/Low-level rendering, audio, input, network, and other hardware-facing driver implementations.
thirdparty/Bundled third-party libraries and dependencies used by the engine.
tests/Engine and subsystem regression tests, validation infrastructure, and test data.
misc/Build scripts, developer utilities, CI helpers, documentation tooling, and supporting project infrastructure.

06 / REDESIGN LAYER

Project-specific engine customization

The redesign module provides a small, isolated foundation for visual and accessibility configuration without duplicating the entire upstream engine.

RedesignConfigRuntime Resource for high contrast, compact mode, reduced motion, accent color, and UI density.
design_tokens.jsonCentralized color, spacing, radius, motion, and accessibility tokens for the redesign system.
register_types.cppEngine module registration point for exposing redesign classes to the Godot runtime.
redesign_examples/Small standalone project demonstrating the configuration concept outside the full editor.

07 / ROADMAP

Build the redesign in layers

Proposed work is separated from existing engine capabilities so the page remains an accurate engineering map.

PHASE 01

Engine baseline

Keep the upstream engine buildable and document current platform/toolchain status.

PHASE 02

Design system

Expand tokens, accessibility controls, theme resources, layout rules, and reusable editor patterns.

PHASE 03

Editor redesign

Apply the design system to docks, inspector, project manager, menus, toolbars, and authoring workflows.

PHASE 04

Runtime UX

Extend accessibility, UI defaults, input behavior, diagnostics, and project-facing runtime presentation.

PHASE 05

Validation

Run regression, compatibility, performance, accessibility, and platform validation across supported targets.

PHASE 06

Release readiness

Document licensing, source provenance, reproducible builds, artifacts, versioning, and release procedures.
